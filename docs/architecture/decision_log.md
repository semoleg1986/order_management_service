# Журнал архитектурных решений (Decision Log)

## ADR-001: Использование Decimal для финансовых данных

**Дата**: 2026-01-22  
**Статус**: Принято  

### Контекст
При обработке цен и сумм в Python использование типа `float` приводит к ошибкам точности из-за особенностей представления чисел с плавающей точкой в двоичной системе (IEEE 754).

### Решение
Мы используем стандартную библиотеку `decimal.Decimal` для всех атрибутов, связанных с деньгами (`price`, `total_price`).

### Последствия
* **Плюсы**: Гарантированная точность вычислений, предсказуемое округление.
* **Минусы**: Незначительное снижение производительности по сравнению с `float`, необходимость принудительной конвертации строк/чисел в `Decimal`.

## ADR-002: Защита коллекций агрегата (Encapsulation)

**Дата**: 2026-01-22  
**Статус**: Принято

### Контекст
Существует риск мутации списка товаров `_items` извне класса `Order` (например, через `.append()`), что приведет к обходу бизнес-валидации и рассинхронизации версии (`_version`).

### Решение
1. Свойство `items` возвращает `tuple(self._items)`.
2. Конструктор выполняет защитное копирование `list(items)`.

### Последствия
* **Плюсы**: Состояние агрегата контролируется только методами `add_item` и `confirm`.
* **Минусы**: Небольшие накладные расходы на копирование коллекции при чтении.

## ADR-003: Применение __slots__

**Дата**: 2026-01-22  
**Статус**: Принято

### Контекст
В системе ожидается создание большого количества объектов заказов и позиций в памяти одновременно.

### Решение
Использование `__slots__` в доменных классах.

### Последствия
* Уменьшение потребления оперативной памяти.
* Запрет на динамическое добавление новых атрибутов в объекты во время выполнения (что также является плюсом для строгости модели).
