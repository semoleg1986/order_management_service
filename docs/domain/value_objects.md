# Объекты-значения (Value Objects)

## Обзор
В нашей доменной модели объекты-значения используются для описания характеристик сущностей. Они не имеют уникального идентификатора и определяются исключительно набором своих атрибутов.

## OrderItem
`OrderItem` представляет собой строку в заказе. 

### Анатомия объекта


1. **Неизменяемость (Immutability)**: Объект реализован через `dataclass(frozen=True)`. Это гарантирует, что после создания состояние позиции нельзя изменить. Если бизнес-логика требует изменить количество, старый объект удаляется, а новый создается.
2. **Валидация при создании**: Инварианты проверяются в методе `__post_init__`. Объект-значение не может быть создан в невалидном состоянии.
3. **Равенство по значению**: Два объекта `OrderItem` считаются идентичными, если совпадают их `product_id`, `quantity` и `price`.

### Математические операции
Объект инкапсулирует логику расчета собственной стоимости:
* `total_price()`: Возвращает результат умножения цены на количество.

### Почему это не Entity?
У товара в заказе нет собственного жизненного цикла. Если мы заменим один айтем на другой с такими же параметрами, для бизнеса ничего не изменится. Нам не нужно отслеживать "историю" конкретной строки заказа, только историю всего Заказа.
